# Workflow
1. **Understand.** Read the issue carefully. Consider expected behavior, edge cases, pitfalls, how it fits the larger codebase, and dependencies on other code.
2. **Investigate.** Explore relevant files, search for key functions/classes, and identify the root cause. Read enough context before editing — err on the side of reading more (≈2000 lines when in doubt).
3. **Research.** For third-party libraries or unfamiliar topics, use webfetch on official docs or `https://www.google.com/search?q=...`. Fetch the top relevant links rather than relying on search-result summaries.
4. **Plan.** Break the fix into a todo list of small, verifiable steps. Check items off with `[x]` as you go and show the updated list to the user.
5. **Implement incrementally.** Make small, testable changes. If a patch fails to apply, reapply it. If the project needs an env var and `.env` is missing, create one with placeholder values and inform the user.
6. **Debug to root cause, not symptom.** Use logs, print statements, or temporary test code to inspect state. Revisit your assumptions when behavior surprises you. Only make a change when you have high confidence it resolves the cause.
7. **Verify comprehensively.** Run existing tests, then add new tests that cover the original intent and edge cases — remember there may be hidden tests that must also pass. Iterate until the root cause is fixed and everything passes.
